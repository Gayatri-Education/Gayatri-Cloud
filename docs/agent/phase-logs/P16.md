## 1. `/plan` — Goal and Scope

- **Master-plan section:** Section 5, Phase P16 (`GAYATRI_CLOUD_PHASE_BY_PHASE_DEVELOPMENT_PLAN.md`)
- **Requirements IDs:** `RQ-028`, `RQ-036`
- **Prerequisite phases and verified statuses:** P00 through P15 all `GREEN`.
- **Explicit in-scope work:**
  1. Billing Database Models (`backend/app/db/models/billing.py`):
     - `SubscriptionPlan`: Tier definition (`free`, `pro_learner`, `institution_standard`, `institution_enterprise`), pricing, intervals, seat limits, and entitlement feature flags.
     - `Subscription`: Active subscription records tied to individual user or organization tenant, status (`active`, `past_due`, `canceled`), period dates, and renewal state.
     - `InstitutionFee`: School/academy tuition and course fee items with due dates and amounts.
     - `FeePayment`: Student payment records against institutional fees.
     - `PaymentTransaction`: Immutable transaction record, gateway transaction ID, idempotency key, webhook signature verification audit.
     - `InvoiceReceipt`: Immutable receipt with sequential invoice number, line items, and tax breakdown.
  2. Billing Domain Service & Gateway Abstraction (`backend/app/domain/billing/service.py`):
     - `PaymentGatewayAdapter` interface and `MockPaymentGateway` implementation:
       - Deterministic mock integration with HMAC-SHA256 cryptographic webhook signature verification.
       - Idempotent event processing preventing duplicate payment charging/crediting.
       - Replay attack defense and signature tampering detection.
     - `BillingService`:
       - Freemium tier enforcement: free tier, individual Pro, and institutional seat-based plans.
       - Clear separation between Gayatri platform subscription fees and third-party AI provider BYOK usage (RQ-014, DEC-C30).
       - Plan upgrades, downgrades, and cancellations.
       - Institution fee schedule management (tuition, lab, materials fees) and collection tracking.
       - Student/guardian fee payment workflows with immediate receipt generation.
  3. REST API Endpoints (`backend/app/api/v1/billing.py`):
     - `GET /api/v1/billing/plans`: List available subscription tiers.
     - `GET /api/v1/billing/subscription`: Retrieve active tenant or personal subscription and entitlements.
     - `POST /api/v1/billing/subscribe`: Subscribe or change plan with idempotency key.
     - `POST /api/v1/billing/cancel`: Cancel subscription at period end.
     - `GET /api/v1/billing/institution/fees`: Organization fee schedules (Org Admin / Academic Admin).
     - `POST /api/v1/billing/institution/fees`: Create institutional fee item.
     - `GET /api/v1/billing/student/fees`: List fees payable for current learner / linked child.
     - `POST /api/v1/billing/student/fees/{fee_id}/pay`: Submit fee payment with idempotency key.
     - `POST /api/v1/billing/webhook`: Cryptographically verified webhook endpoint.
     - `GET /api/v1/billing/invoices`: Retrieve past invoices and payment receipts.
  4. Frontend Billing Architecture & Components:
     - Types in `frontend/src/lib/types/billing.ts`: `SubscriptionPlan`, `SubscriptionRecord`, `InstitutionFeeItem`, `StudentFeePayment`, `InvoiceReceiptItem`.
     - Client methods in `frontend/src/lib/api-client.ts`.
     - Components in `frontend/src/components/billing/`:
       - `BillingNav.tsx`: Tab navigation for billing sub-views.
       - `PlanSelectorCards.tsx`: Freemium tier presentation, feature comparison, upgrade/downgrade actions.
       - `EntitlementsBadge.tsx`: Current tier, renewal status, and capability badges.
       - `InstitutionFeeManager.tsx`: Org fee schedule editor and collections progress.
       - `StudentFeePaymentCard.tsx`: Fee breakdown, due date warning, and payment button.
       - `InvoiceHistoryTable.tsx`: Invoice history with receipt view.
     - Pages (Next.js 14 App Router):
       - `/billing`: Primary billing overview & subscription status.
